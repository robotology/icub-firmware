# cmsisrtx

CMSIS-RTX (Keil RTX5) 5.9.1 with only a few marked changes (see "Changes made to the original RTX"), built with Arm Compiler 6
(armclang) as a library, one per core of the STM32H7 dual-core and in two flavours, **debug** and **fast**:

| lib | core | flavour |
|---|---|---|
| `lib/cmsisrtx.debug.cm4.lib` | Cortex-M4F | Event Viewer bridge on, stack check on, stack watermark on |
| `lib/cmsisrtx.debug.cm7.lib` | Cortex-M7, double precision FPU | as above |
| `lib/cmsisrtx.fast.cm4.lib` | Cortex-M4F | no Event Viewer bridge, no stack check, no stack watermark |
| `lib/cmsisrtx.fast.cm7.lib` | Cortex-M7, double precision FPU | as above |

The targets of `proj/cmsisrtx.uvprojx` are named `debug.cm4`, `debug.cm7`, `fast.cm4`, `fast.cm7`: each one builds `obj/<target>/cmsisrtx_<flavour>_<core>.lib` and the post-build step copies
it to `lib` with the final name (uVision cuts a dotted `OutputName` at the last dot, so the dots are added by the copy). The flavour is selected by the macro `CMSISRTX_FAST`, defined by the `fast.*` targets (instead of
`CMSISRTX_EVENTVIEWER` of the `debug.*` ones): `src/extra/RTE_Components.h` undefines `CMSISRTX_EVENTVIEWER` if `CMSISRTX_FAST` is
defined, and `cfg/RTX_Config.h` sets `OS_STACK_CHECK` and `OS_STACK_WATERMARK` to 0. Everything else is identical, so use the fast lib
for the performance measures (and for the release) and the debug one while developing.
No CMSIS-Pack / RTE component is used: everything needed is in this folder.

| versions | |
|---|---|
| CMSIS-RTX | v5.9.1 (CMSIS-RTOS2 API 2.3.0), `src/CMSIS-RTX`, from https://github.com/ARM-software/CMSIS-RTX (docs and examples removed) |
| CMSIS 6 | v6.4.0, `src/CMSIS_6`: only the Core headers for M4/M7, `cmsis_os2.h`, `os_tick.h`, `os_systick.c` |

```
cmsisrtx
├── api    cmsisrtx.h (the only header of the users; generated by src/extra/make_api.py)
├── cfg    the configuration of RTX, compiled INTO the lib (first in its include path, for the whole kernel):
│            RTX_Config.h/.c   configuration (idle thread, error notify: weak defaults, the application can redefine them)
│            cmsisrtx_lib.c    includes src/CMSIS-RTX/Source/rtx_lib.c (osRtxConfig, static memory, C lib mutex/libspace hooks)
│                              and checks at compile time the constants of cmsisrtx.h against rtx_os.h
├── lib    cmsisrtx.{debug,fast}.{cm4,cm7}.lib  (copied here by the post-build step of each target)
├── proj   cmsisrtx.uvprojx, targets debug.cm4, debug.cm7, fast.cm4, fast.cm7
└── src    CMSIS-RTX, CMSIS_6, extra (cmsisrtx_device.h, RTE_Components.h used only to build the lib, make_api.py)
```

## What is in the lib
rtx_kernel, thread, delay, timer, evflags, mutex, semaphore, memory, mempool, msgqueue, system, evr (events disabled
with `EVR_RTX_DISABLE`), `irq_armv7m.S` via the wrapper `src/extra/cmsisrtx_irq.c` (a .S file would go to armasm; the wrapper is compiled by armclang with `-x assembler-with-cpp`) (`SVC_Handler`, `PendSV_Handler`, `SysTick_Handler`), `os_systick.c` (OS Tick on SysTick).
Also `cfg/RTX_Config.c` and `cfg/cmsisrtx_lib.c`. The whole lib is built with `cfg/RTX_Config.h` (`..\cfg` is the first include
path); `src/CMSIS-RTX/Library/RTX_Config.h` of the original RTX is not used any more.
`OS_Tick_*` of the lib are weak: the application can replace them.

## How to use it in an application (per core)
1. link one of `lib/cmsisrtx.debug.cm4.lib`, `lib/cmsisrtx.fast.cm4.lib`, `lib/cmsisrtx.debug.cm7.lib`, `lib/cmsisrtx.fast.cm7.lib`;
2. nothing of RTX is compiled by the application: no `_RTE_`, no RTX include paths, no `RTE_Components.h`;
2. add the path `api` to the project and `#include "cmsisrtx.h"` in the code (it contains `cmsis_os2.h` and `os_tick.h`;
   the sizes of the control blocks for objects with user memory are `CMSISRTX_*_CB_SIZE`);
3. the application must provide `SystemCoreClock`; `SysTick_Handler`, `SVC_Handler`, `PendSV_Handler` are the ones of the lib
   (they override the `[WEAK]` ones of the startup file). `rtx_lib.c` references `irqRtxLib` (defined in `irq_armv7m.S`), so the
   handlers object is pulled from the lib; if a weak handler still wins, check the map file.

Example: the target `amcmj1.2cm4-master` of `board/amcmj1/examples/appl.gateway.01/proj/amcmj1.appl.gateway.01.uvprojx`,
with `-DEMBOT_USE_rtos_cmsisrtx` and `embot/os/embot_os_rtos_cmsisrtx.cpp` (the embot::os::rtos layer on top of this lib).

The values of `cfg/RTX_Config.h` that differ from the original RTX are marked with `cmsisrtx/embot:`.

## The API header

`api/cmsisrtx.h` is the only header that an application includes. It is **generated, do not edit it**: `src/extra/make_api.py`
writes it (`python3 src/extra/make_api.py`, from any folder). It is not part of the build: run it only when it must change.

It contains:
- `cmsis_os2.h` and `os_tick.h`, copied verbatim from `src/CMSIS_6` (they keep their include guards);
- a final section "cmsisrtx extras", which is written inside the script: the sizes of the control blocks of RTX
  (`CMSISRTX_THREAD_CB_SIZE`, `CMSISRTX_MUTEX_CB_SIZE`, ..., and the macros for the memory of queues and pools), needed to create the
  RTOS objects with user memory (e.g. with `new`), and `cmsisrtx_config_t` with `cmsisrtx_config_set()` and its result codes
  (see "Run-time configuration").

The extras cannot get out of step with RTX: `cfg/cmsisrtx_lib.c` has a `_Static_assert` for each size, which compares it with the one of
`rtx_os.h`. If RTX is updated and a size changes, the lib does not compile and tells which one.

Run the script again when RTX or CMSIS 6 are updated, or when the extras inside the script are changed (see "Update RTX").

## What is fixed at build time (RTX_Config.h, rebuild the lib to change)
- `OS_THREAD_LIBSPACE_NUM` (16): maximum number of live threads that use the C library (96 bytes each). The 17th gets
  `osRtxErrorClibSpace` in `osRtxErrorNotify()`.
- `OS_DYNAMIC_MEM_SIZE` (1024): not used for the objects of the application (they are created with user memory), but the Arm
  C library takes its mutexes from it before main(). How to find the real need: comment in `cfg/RTX_Config.h`.
- `OS_ROBIN_ENABLE` (0) and `OS_ROBIN_TIMEOUT` (5 ticks): round-robin among threads of the same priority is off.
- `OS_STACK_CHECK` and `OS_STACK_WATERMARK` (1 in the debug libs, 0 in the fast ones: `CMSISRTX_FAST`), `OS_PRIVILEGE_MODE` (1).
- the default of the tick, of the idle / timer stacks and of the queues: only a fallback, see "Run-time configuration".
Everything else (`*_OBJ_MEM`, `*_NUM`, safety, zones, watchdog, `OS_EVR_*`) is off or unused.

## Event Viewer (threads in Keil uVision, ITM port 31)

As the old oosiit/osal did, the lib can tell the uVision *Event Viewer* which thread is running, each thread
being named after its entry function (e.g. `tCTRL`). It is on in the `debug.*` libs (`CMSISRTX_EVENTVIEWER` is
defined by those targets) and off in the `fast.*` ones (`CMSISRTX_FAST` removes it); **rebuild the lib** after any change.

- `src/CMSIS-RTX/Include/rtx_evr.h` (changed, marked `cmsisrtx/embot`): under the macro, `EvrRtxThreadCreated`,
  `EvrRtxThreadSwitched`, `EvrRtxThreadDestroyed` call `src/extra/cmsisrtx_eventviewer.c`.
- that file calls `eventviewer_init/load/unload/switch_to()` of `libs/midware/eventviewer` (STRONG references: the application
  must have `eventviewer.c` in its project, otherwise the link fails; with weak ones armlink dropped the eventviewer
  functions as unused and the bridge did nothing). The module is the same used by
  `embot::app::scope::SignalEViewer`, so the two share the ITM state.
- ids: idle = `ev_ID_idle`; other threads = `ev_ID_first_ostask` + slot (max 94 alive at the same time).
- to see it: ULINKpro + trace configured in Options / Debug / Settings / Trace (and the .ini), then
  Debug / OS Support / Event Viewer. Nothing is sent if the ITM is not enabled.
- the Event Viewer learns the thread names only from the "load" messages sent at thread creation: if its window is opened
  after the start, they are lost. So each thread is announced again, just before being switched in, if the last announce
  is older than `CMSISRTX_EV_REANNOUNCE_S` (default 1 s, 0 = off). The idle thread is shown as `tIDLE` (weak empty function in the bridge, overridable) and the init thread as `tINIT` (its entry function).
- The init thread (`tINIT`, it runs once at the start and exits) is a "sticky" entity: when it is destroyed its id is not
  unloaded nor reused, and its name is announced again with the others (otherwise its segment is shown as `<No Address>`).
- debug: watch `cmsisrtx_ev_diag` (created, switched, notready, loads, switches). `notready` growing means that
  `eventviewer_init()` fails (ITM/trace not enabled when the threads are created): nothing can be sent then.
- `eventviewer_load/_unload` now run with the interrupts disabled (two writes on the ITM port: a preempting thread switch
  notification would corrupt the stream and the viewer would get lost).
- limits: the switch is notified when RTX elects the next thread, a few microseconds before PendSV switches;
  ISRs (systick, pendsv, svc, ...) are not shown.

## Run-time configuration (tick, idle / timer stacks, timer queue, ISR queue)

Original RTX fixes them at build time with `RTX_Config.h`. Here they can be set at run time, with a small and marked
change of RTX (macro `CMSISRTX_RUNTIME_CONFIG`, default on; `=0` in the lib project **and** in the application gives back
the original behaviour):

- `rtx_os.h` / `rtx_lib.c` (marked `cmsisrtx/embot`): `osRtxConfig` is in RAM, not in flash.
- `src/extra/cmsisrtx_config.c`, included by `cfg/cmsisrtx_lib.c` (same translation unit of `osRtxConfig` on purpose, so no
  project change is needed): `int32_t cmsisrtx_config_set(const cmsisrtx_config_t *)`, declared in `api/cmsisrtx.h`.
  It validates everything first (nothing is changed if a value is wrong) and returns `CMSISRTX_CONFIG_OK`,
  `_ERR_PARAM`, `_ERR_STATE` (kernel already running) or `_UNSUPPORTED` (built with `CMSISRTX_RUNTIME_CONFIG=0`).
- the memory (stacks, timer queue, ISR queue) is given by the caller, e.g. calloc, and must stay valid forever.
- when: the kernel is initialised before `main()` (the C library needs the RTX mutexes from its own start-up), so the
  call goes after that and before `osKernelStart()`. What the kernel reads at `osKernelStart()` (tick, idle thread, timer
  thread, timer queue) is simply changed; the ISR queue, copied by the initialisation, is patched in `osRtxInfo` too.
- `embot::os::rtos::scheduler_init()` calls it with the values of `scheduler_props_t::prepare()`: tick = 1e6 / ticktime,
  idle and timer stack sizes; the lengths of the timer queue (32) and of the ISR queue (128) are in the cpp.
- `cfg/RTX_Config.h`: with the run-time configuration the static idle / timer stacks, timer queue and ISR queue are only
  a small fallback (256 / 512 bytes, 4 and 16 items), used if `cmsisrtx_config_set()` is not called. `OS_TICK_FREQ` is
  the default of the tick.
- limits: the priority of the timer thread can be changed by the struct but `scheduler_init()` keeps `OS_TIMER_THREAD_PRIO`;
  the memory of the control blocks of idle and timer threads and of the timer queue stay the static ones of `rtx_lib.c`.

## Changes made to the original RTX

The RTX sources in `src/CMSIS-RTX` are CMSIS-RTX 5.9.1 and they are modified only where listed here. All the changes are
small, guarded by a macro, and marked with the text `cmsisrtx/embot`.

### How to find them
- All the marked places (in the RTX sources, in `cfg` and in `src/extra`):
  `grep -rn "cmsisrtx/embot" src cfg`
- The exact difference with the original: the first commit of the lib (`b5321fa`, "Add cmsisrtx: unmodified CMSIS-RTX 5.9.1")
  contains the sources as they were downloaded, so:
  `git diff b5321fa HEAD -- src/CMSIS-RTX src/CMSIS_6 cfg`
  (or `git log -p -- <file>` for the history of one file). Without git: compare `src/CMSIS-RTX` with the same release of
  https://github.com/ARM-software/CMSIS-RTX.

### What they are
Files of the RTX itself (3 files, 28 lines in total):

| File | Change | Macro |
|---|---|---|
| `src/CMSIS-RTX/Include/rtx_os.h` | `osRtxConfig` declared writable (not `const`), so that it can be placed in RAM | `CMSISRTX_RUNTIME_CONFIG` (default 1) |
| `src/CMSIS-RTX/Source/rtx_lib.c` | `osRtxConfig` defined in RAM (no `.rodata` section) | `CMSISRTX_RUNTIME_CONFIG` |
| `src/CMSIS-RTX/Include/rtx_evr.h` | `EvrRtxThreadCreated/Switched/Destroyed` call the functions of `src/extra/cmsisrtx_eventviewer.c` | `CMSISRTX_EVENTVIEWER` |

With `CMSISRTX_RUNTIME_CONFIG=0` and without `CMSISRTX_EVENTVIEWER` the three files are the original ones, functionally.

Files that are ours (not in the original RTX): everything in `src/extra` (`cmsisrtx_config.c`: `cmsisrtx_config_set()`;
`cmsisrtx_eventviewer.c`: Event Viewer; `cmsisrtx_irq.c`: wrapper that lets armclang assemble `irq_armv7m.S`;
`cmsisrtx_device.h`, `RTE_Components.h`, `make_api.py`), `api/cmsisrtx.h`, `cfg/cmsisrtx_lib.c`, `proj`.

Files of the original that are meant to be edited (the configuration):
- `cfg/RTX_Config.c`: only the include of the device header was added; idle thread and `osRtxErrorNotify` are the original weak ones.
- `cfg/RTX_Config.h`: the values that differ from the original are marked `cmsisrtx/embot:` with the original value
  in the comment: round-robin off (original 1), `OS_STACK_WATERMARK` 1 (original 0), `OS_TIMER_THREAD_PRIO` 55 (original 40),
  `OS_DYNAMIC_MEM_SIZE` 1024, the sizes of the ISR queue, idle / timer stacks and timer queue (fallbacks, the real ones are set at
  run time). The original reduced `src/CMSIS-RTX/Library/RTX_Config.h` is no longer used.

The Arm C library hooks (`_mutex_*`, libspace) are the original ones of `rtx_lib.c`.

## Maximum speed of the library

What costs time in RTX, and what can be done about it. Nothing here is measured: measure on the target (DWT cycle counter,
`DWT->CYCCNT`) before and after each change.

### Compiler (lib project options)
- Optimization `-Ofast` (or `-O3`): already the setting of all the targets.
- **Link-Time Optimization must be OFF** in the lib. With LTO the objects of the `.lib` contain LLVM bitcode and the application
  link fails with `L6115U: File cmsisrtx.fast.cm4.lib(rtx_kernel.o) contains section .llvm.lto with LLVM bitcode but LTO mode is not
  enabled`. (LTO could work only if the application is built with LTO too; it brings almost nothing, the hot code is all inside
  the kernel files.)
- Keep "One ELF section per function" on (the linker removes what is not used) and the software stack check (`-fstack-protector`)
  off; build the lib for the right core (`CMSISRTX_CM4` / `CMSISRTX_CM7`, FPU on), never a generic one.

### The fast libs
`lib/cmsisrtx.fast.cm4.lib` and `lib/cmsisrtx.fast.cm7.lib` already have, imposed by the macro `CMSISRTX_FAST`: no Event Viewer bridge,
`OS_STACK_CHECK` 0, `OS_STACK_WATERMARK` 0. They are the libs to use for comparing with the old osal. The rest of this section is what
can still be changed.

### Configuration (`cfg/RTX_Config.h`, rebuild the lib)
| Parameter | For speed | Effect |
|---|---|---|
| `OS_STACK_CHECK` | 0 (fast libs) | no stack overrun check at every thread switch (it is in `PendSV` and in the thread switch code). Keep it 1 while debugging |
| `OS_STACK_WATERMARK` | 0 (fast libs) | no stack filling at thread creation (only the creation is slower, not the switch) |
| `OS_ROBIN_ENABLE` | 0 (as is) | no round-robin: no extra work at every tick |
| `OS_SAFETY_FEATURES`, `OS_OBJ_PTR_CHECK`, `OS_SVC_PTR_CHECK` | 0 (as is) | no checks of pointers, zones, watchdog |
| `OS_EVR_*` and `EVR_RTX_DISABLE` | disabled (as is) | no event recorder calls in the kernel |
| `OS_TICK_FREQ` / `tick_freq` of `cmsisrtx_config_set()` | the lowest that the application accepts | every tick is an interrupt of `SysTick` that scans the delay list: 1 kHz costs ten times 100 Hz |
| `OS_PRIVILEGE_MODE` | 1 (as is) | privileged threads: no mode switch |

### Defines (lib project options)
- **`CMSISRTX_EVENTVIEWER` is not defined in the fast libs**, and must not be in the build used for measures and in release: with it every thread switch writes on the
  ITM port 31 (and a thread creation too), which is usually the biggest part of the cost of a switch. Without it the hooks are not
  compiled at all. Keep `EVR_RTX_DISABLE` always.

### Application
- Priorities: with no round-robin, threads of different priorities are scheduled with the minimum work. Do not use `osThreadYield()`
  in a loop and do not use delays shorter than a tick to wait for something that can be a flag, an event or a message.
- Prefer thread flags / event flags to message queues and semaphores for notifications (shorter paths), and do not create or
  delete objects at run time in the hot path (create everything at start, with user memory).
- `osKernelLock`/`osKernelSuspend` and `__disable_irq()` around long code add latency to the tick and to `PendSV`.
- ISR to thread: from an ISR the RTX functions go through the ISR queue (`isr_queue` of `cmsisrtx_config_t`): keep it large enough, an
  overflow calls `osRtxErrorNotify(osRtxErrorISRQueueOverflow)`.

### Memory (the biggest gain on the cm7, none on the cm4)
- cm7 (STM32H747): place the kernel code (`rtx_*.o`, the handlers) in ITCM and `osRtxInfo`, the thread control blocks and the stacks
  of the fast threads in DTCM, with the scatter file of the application. The context switch is made of loads and stores of these
  structures, so the wait states of the memory are the cost.
- cm4: there are no TCM; keep code and data out of the slow external memories and out of regions shared with the bus masters
  that are busy (e.g. the Ethernet DMA buffers).

## The cm7 on cmsisrtx, with the fast RAM

Target `amcmj1.1cm7-cmsisrtx` of `board/amcmj1/examples/appl.gateway.01/proj/amcmj1.appl.gateway.01.uvprojx` (the target
`amcmj1.1cm7-master` is untouched and still uses osal). It is a copy of it that links `lib/cmsisrtx.debug.cm7.lib` (use
`cmsisrtx.fast.cm7.lib` for the measures), compiles `embot_os_rtos_cmsisrtx.cpp` and has `-DEMBOT_USE_rtos_cmsisrtx
-DEMBOT_OS_RTOS_CMSISRTX_FASTRAM`. Its scatter file is `cfg/amcmj1.1cm7-lwip-0offset.fastram.sct`: the one of the master plus

| region | address | content |
|---|---|---|
| `RW_ITCM` | 0x00000000, 64 kB | code of `cmsisrtx.*.cm7.lib` (kernel, SVC / PendSV / SysTick handlers) and of `embot_os_rtos_cmsisrtx.o`; copied from the flash by the scatter loading before `main()` |
| `RW_DTCM` | 0x20000000, 128 kB | data of `cmsisrtx.*.cm7.lib` (`osRtxInfo`, `osRtxConfig`, libspace...) and the section `.bss.cmsisrtx_fastram` |

`EMBOT_OS_RTOS_CMSISRTX_FASTRAM` makes `embot_os_rtos_cmsisrtx.cpp` take from `.bss.cmsisrtx_fastram` (64 kB, change it with
`-DEMBOT_OS_RTOS_CMSISRTX_FASTRAM_SIZE=<bytes>`) the memory of the objects that the context switch touches: control block and stack of
every thread, idle and timer stacks, timer queue, ISR queue. When it is full the heap is used, as without the macro, so nothing
fails; to see how much is left look at `embot::os::rtos::cmsisrtx::fastram.freebytes()` in the debugger. Mutexes, queues, timers and
the `new` of the application stay in the heap. DTCM is not reachable by the DMA of the peripherals: never put buffers of the
peripherals there (the stacks are fine).

What to expect: DTCM has no wait states and no cache, so the data of the scheduler and the stacks are as fast as it gets; ITCM mostly
makes the time of the kernel code and of the handlers constant, because the I-cache is already enabled by the bsp (D-cache is not).
The TCMs are enabled out of reset on the STM32H7. Not measured: use the fast lib and DWT, with and without the macro.

If the linker says that a region overflows: ITCM, remove `embot_os_rtos_cmsisrtx.o (+RO)` from the scatter; DTCM, reduce the size of
the fast ram. The map file shows the content of every region.

## Update RTX
Copy the new RTX in `src/CMSIS-RTX` (and the needed CMSIS 6 files), re-run `python3 src/extra/make_api.py`, check that
the `_Static_assert` in `cfg/cmsisrtx_lib.c` still pass (update the sizes in `make_api.py` if not), rebuild all the targets.
The RTX files changed by us are marked `cmsisrtx/embot` and must be applied again to the new version: `Include/rtx_os.h`
(run-time configuration), `Source/rtx_lib.c` (same), `Include/rtx_evr.h` (event viewer). `git log -p` on them shows how.

## Status
The uvprojx was generated without Keil: sources (kernel and `cfg` files, built with `cfg/RTX_Config.h`) and `api/cmsisrtx.h` were compile-checked with clang (thumbv7em, M4F and M7)
and the unresolved symbols of lib+cfg are only `SystemCoreClock`, the C library (`memset/memcpy`) and the weak linker symbols of RTX.
The `.lib` files are produced by the first build with armclang in uVision.
